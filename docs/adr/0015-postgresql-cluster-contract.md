# ADR 0015 — PostgreSQL is a foundation, not a supported option, and the cluster it needs is a written contract

- **Status:** Accepted
- **Date:** 2026-09-03
- **Related:** ADR 0004 (the read layer), ADR 0007 (observability does not gate
  correctness), ADR 0010 (warehouse policy lives in SQL)

## Context

gobit does not *support* PostgreSQL. gobit is *written on* PostgreSQL. There is
no abstraction layer and nothing claims there is one. That is not the problem.

The problem is that the dependency has never been written down as a contract,
and this week that cost a blocker. `deploy/docker-compose.yml` created the
cluster with `--locale=C`; C folds ASCII only; a shopper searching `çanta` got
zero results for a product titled `Çanta`. No error, no log line, no metric —
the search box returned an empty list. Measured on a real server:

    GET /store/v1/products?q=çanta   ->  0 results
    GET /store/v1/products?q=Çanta   ->  1 result

It was not a plugin problem: the storefront's own filter is
`title ILIKE '%' || $q || '%'`, so an installation with no plugin at all was
broken the same way. Fourteen ADRs, a README with a "Known limits" section, and
a test suite with mutation discipline — and none of them mentioned locale,
because the cluster had never been treated as something with requirements.

### Where the dependency actually lives

It is not diffuse. It is enumerable, and enumerating it is half of this decision:

- **Driver and generation.** pgx/v5 + pgxpool; repositories generated by sqlc in
  the PostgreSQL dialect.
- **Batch reads.** `= ANY($1::text[])`. The entire no-N+1 read layer rests on
  it — `ListMany`, `ListManyByTo`, `ListVariantsByProductIDs`, the sales-channel
  visibility predicate. On a database without array parameters this pattern does
  not exist.
- **Partial unique indexes.** `UNIQUE (handle) WHERE deleted_at IS NULL`. This is
  not a tuning knob; it is the business rule. "A deleted product releases its
  handle" is a sentence written in an index.
- **`jsonb` metadata, `timestamptz` (235 columns), `ON CONFLICT` (31 files).**
- **Search.** The storefront's `ILIKE` filter and searchpg's
  `to_tsvector`/`websearch_to_tsquery`/GIN. Both depend on the cluster's CTYPE.
- **Concurrency.** Advisory locks in the spending rule; row locks on the stock
  path, with a lock ORDER (`item -> level -> reservation`) the fake store records
  because the order is a contract.
- **Runtime DDL.** `core/link` runs `CREATE TABLE` and `CREATE INDEX` at EVERY
  startup (`link.Define`), because a link's schema is declared in code rather
  than in a migration directory. sqlc cannot see those tables, which is why the
  queries touching them are hand-written.
- **Migrations.** golang-migrate, with a separate `<module>_schema_migrations`
  table per module.
- **No schema qualification anywhere.** Every query relies on the default
  `search_path` resolving to the schema the migrations wrote into.

The layer-purity rule keeps pgx below the repository, so the SERVICE layer talks
to an interface. But that interface has exactly one real implementation. The seam
is at the repository, not at a query builder, and pretending otherwise would be
the kind of claim this repository writes ADRs to avoid.

## Decision

**1. PostgreSQL is a foundation. There will be no second database.**

The reason is not taste. The first three items above are not portable: without
array parameters the batch reads collapse into dynamically built `IN` lists;
without partial unique indexes the soft-delete-plus-uniqueness rule has to be
faked with a sentinel column; without `jsonb` metadata becomes a text column.
And the cost is not "twice the queries" — this repository's whole discipline is
that every rule has ONE definition, and a second dialect makes every invariant
dialect-dependent. The audience writing commerce in Go is already on PostgreSQL:
the gain is small and the price is the architecture.

**2. The cluster gobit needs is a written contract, and this is it.**

| requirement | value | what breaks otherwise |
|---|---|---|
| version | 16 is the only version TESTED (CI and every integration test run `postgres:16-alpine`) | the newest feature used is `websearch_to_tsquery` (11) and `GENERATED ALWAYS AS IDENTITY` (10), so older majors may well work — but untested is untested, and this table says what is promised, not what might happen |
| encoding | `UTF8` | a Turkish product title cannot be stored at all; the insert fails |
| CTYPE | a locale that folds non-ASCII case (`C.UTF-8` and friends) | search silently returns nothing — the failure this ADR exists for |
| collation | free; `C` (byte order) is what the shipped compose uses | nothing; ordering determinism is independent of case folding |
| extensions | **none** | today gobit requires zero extensions; `grep -r "CREATE EXTENSION"` returns nothing |
| privileges | the application role must be able to run DDL **at runtime**, not only during migration | `link.Define` fails at startup; a restricted production role hits this on day one |
| `search_path` | must resolve to the schema the migrations wrote | every query fails with "relation does not exist" |
| timezone | free | every timestamp column is `timestamptz` and Go writes UTC; the session zone affects display only |

**3. The contract is enforced by a PROBE that tests BEHAVIOR, not configuration
names.**

This is the decision that makes the rest useful, and it comes from a fact about
real deployments: on RDS, Cloud SQL or Neon you do not choose the `initdb`
arguments. Fixing `docker-compose.yml` fixes the laptop and nothing else. The
probe is what travels.

Behavior rather than names, because a name is a proxy and proxies drift. The
check does not read `datctype` and compare it against a list of blessed strings;
it asks the database to fold two letters and looks at the answer. An unusual but
correct locale passes, and a locale that merely *looks* right does not.

It tests BOTH search paths, and that is not thoroughness for its own sake — they
disagree. Measured on the shipped image:

    --locale=C                        ILIKE ✗   to_tsvector ✗
    --locale=C.UTF-8                  ILIKE ✓   to_tsvector ✓
    --locale=C --locale-provider=icu  ILIKE ✓   to_tsvector ✗

A check that asked only about `ILIKE` would hand the ICU installation a clean
bill of health while its product search stayed broken. Half a fix that looks like
a fix is worse than none.

**4. The probe reports; it stops startup only where continuing would be SILENT.**

A cluster that is missing a function fails loudly at the first query, and a loud
failure needs no probe. The probe exists for the other kind: a query that
succeeds, returns nothing, and looks like an empty catalog. So case folding is
warned about and startup continues — an all-ASCII catalog works perfectly on a C
cluster, and refusing to open would break installations with nothing wrong with
them.

This is also why the probe has exactly ONE check today, and why that is not an
omission. Look down the contract table and ask of each row how it fails: a
non-UTF8 encoding rejects the insert; a missing privilege stops `link.Define` at
boot; a wrong `search_path` makes every query say "relation does not exist"; a
version below the floor makes a function call fail. Every one of them arrives
with a message. Case folding is the only row that fails by returning a correct,
empty, silent answer — so it is the only row that has earned a probe. Adding
checks for the loud rows would be branches nothing can distinguish from their own
absence, and this repository removes those rather than collecting them.

**5. Every new requirement enters through this ADR and the probe, in the same
change.** A required extension, a raised version floor, a needed privilege: the
table above grows, the probe grows with it, and the operator finds out at startup
rather than from a customer.

## Consequences

- **Exposing `core/db` makes pgx a permanent public dependency.**
  `db.Pool.Pool()` hands out a raw `*pgxpool.Pool` and searchpg already uses it,
  because a plugin that brings its own module needs to write its own repository.
  There is no way around it, and it is the decision that formally ends any claim
  that "PostgreSQL is an implementation detail". This ADR is deliberately dated
  BEFORE the one that opens the surface: telling users "actually you needed
  C.UTF-8" after they have installed is breaking their installation.
- An existing data directory keeps the locale it was created with. The compose
  fix helps new installations only; an existing one needs a dump and restore, and
  the probe's warning says so.
- The contract is a promise, so widening it is a breaking change for operators
  even when no Go signature moves.

## What this cannot express

- **A managed provider changing under the installation.** The probe runs at
  startup. A provider that alters a setting during a maintenance window is not
  noticed until the next restart.
- **Whether the version floor is really 16.** Nobody has run the suite on 14 or
  15. The table says "tested", which is the only honest word available.
- **Privileges that are present at startup and revoked later.** `link.Define`
  runs once per boot; a role narrowed afterwards keeps working until the next
  deploy adds a link.
- **Anything about the data.** The contract is about the cluster. A catalog with
  mixed encodings inside a UTF8 database is a different problem.

## Rejected options

**An abstraction layer over the database.** It would have to give up array
parameters, partial unique indexes and `jsonb` — that is, the three things the
read layer, the uniqueness rules and the metadata model are built on. What
remained would be portable and would no longer be this system.

**Supporting a second database as a build tag or a driver.** Every invariant
would become dialect-dependent, and the repository's central discipline is that a
rule has one definition. Two dialects means every SQL-encoded rule is written
twice and the two drift silently — the exact failure mode the sales-channel
visibility template was written to prevent.

**Reading the locale name instead of testing behavior.** Cheaper and wrong for
the reason given in decision 3, and it would also have to keep a list of blessed
locale names up to date forever.

**Refusing to start on a C-locale cluster.** It would break every English-only
installation, which works correctly. A warning that names the affected query and
the fix is the proportionate answer.

**Documenting the requirement in the README and stopping there.** That is what
was effectively in place — the searchpg plugin's godoc even stated the UTF-8
locale precondition — and the compose file shipped the opposite anyway. A comment
cannot fail a deployment; a probe can speak.

## Reopening the decision

Reopen when the first EXTENSION becomes required. `pg_trgm` is the standing
candidate: the storefront's `ILIKE '%q%'` has a leading wildcard and therefore
cannot use any B-tree index, so search is a full scan even with the locale fixed.

The trade was measured rather than argued, on the 52k-product fixture:

| | without `pg_trgm` | with `pg_trgm` + GIN |
|---|---|---|
| `?q=` count | 58.9 ms (seq scan) | **2.2 ms** (bitmap index scan) |
| `?q=` list, LIMIT 20 | 12.6 ms | **1.8 ms** |

So the gain is real and it is the difference between search that scales with the
catalog and search that does not. The price is one row of the contract table
moving from "none" to a list, which on a managed provider means an allow-list
entry — `pg_trgm` happens to be on every major provider's list, which is why it
is the candidate rather than a custom function.

It is still not taken here. Adding a required extension is a change to what
operators must provide, and this ADR exists precisely so that such a change is a
decision with a date on it rather than the side effect of a performance fix.

Reopen if a managed provider that a real installation wants to use cannot satisfy
a row of the table. The answer then is not to weaken the row silently; it is to
decide, in writing, whether gobit runs there.
