# ADR 0183 — A stranger starts with one command

**Summary:** The README's first command starts a project with `go run` of the
released binary, and a gate holds that command to the tree. A binary not told
its version calls itself by the version the toolchain stamped for it.

- **Status:** Accepted
- **Date:** 2026-09-25

Measurement: [measurements/0183](../measurements/0183-the-first-command.md)

## Context

v0.9.0 made the library importable, and ADR 0182 let a released binary start a
project, but nothing a stranger reads first said how. The README's quick start
runs this repository, not a project that embeds it. Measured after the release,
`go run github.com/bdrtr/gobit/cmd/server@v0.9.0 new shop` already wrote a
project requiring v0.9.0: `go run` of a module at a version stamps that
version, so ADR 0182's sentence that `go run` writes `(devel)` holds only for
`go run .` in a checkout (D133). The same binary called itself `gobit dev`,
because the name in the startup log, the OpenAPI document and every trace came
only from `-ldflags`.

## Decision

The README's first command is `go run github.com/bdrtr/gobit/cmd/server@latest
new <dir>`, and a gate holds its package path and verb to the tree. A binary not
told its version calls itself by the version the toolchain stamped for its own
module, and "dev" only when it stamped none.

## Consequences

The command needs no install step and no binary name. The version it runs is
the version the project requires. `go install` of the same path still names
the binary `server`, and the README does not use it.

The README does not copy the next steps. `new` prints them and the generated
README keeps them, so there is one copy to keep true.

The gate cannot run the command, because `@latest` is the proxy's answer and
not this checkout's. It checks both halves against the tree the next release
is cut from: the path is a main package, and the verb is a usage line in that
binary's help.

A clean build names itself by its tag or pseudo-version, and a tree with changes
adds `+dirty`. A name is not something the proxy has to serve, so the stamp
that ADR 0182 refuses for a go.mod is the right answer here. `go run .` in a
checkout, a test binary and `go build main.go` are `dev`. A version the build
set answers first, so `make build` and the Docker image name themselves as
before.

An embedding project's binary names itself by its own module's version, because
its main module is the project. `cmd/server`, the generated `main.go` and the
starter now leave `version` empty. A project generated by v0.9.0 passes "dev"
explicitly, and keeps printing it until that line is emptied.

## Rejected

- **Renaming `cmd/server` to `cmd/gobit`.** It would name an installed binary
  after its help text, and `go run` needs no name.
- **Treating "dev" as unset.** A value the caller passed is the caller's
  answer, and a sentinel gives one string two meanings.
- **The library's version as the program's name.** In an embedding binary
  that names gobit, not the shop.
- **Copying the steps into the README.** It would be a second copy of what
  `new` prints.
